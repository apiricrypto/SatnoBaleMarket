# Market business review implementation plan

Goal: implement the user-approved Bale Market side of reviewed company/person identification and supplier/buyer routing; deliver a concrete CRM handoff contract without enabling live sends or changing the external CRM.

Architecture: conservative suggestions from original ad text; optional versioned business-profile JSON in the existing review row, validated and audited by the server. Review UI collects the declared name, entity type, supplier/buyer/both roles, named contact, contact verification and evidence. Queue snapshots include source references, all contacts and explicit intended CRM intake. New business-intake payloads are blocked from live delivery until a future jointly approved receiver implementation exists; legacy payload behavior stays intact.

Constraints: preserve FastAPI/HTML/CSS/JS, existing permissions, source text, source references, hourly Sync and existing outbox/sent rows. Add one idempotent SQLite column only; old client edits preserve it. No company/contact is created locally or in CRM, no entity merge, no dependency, no live configuration or production change. Name mentioned in an ad is not a verified legal name or a verified relationship for every phone. Confirmation requires a primary contact, evidence note and identified reviewing user.
